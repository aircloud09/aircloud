# 근거 문서 — agent-office

이 포크(`heejunKIM01/agent-office`)가 무엇을 만들지 정하는 문서다. 원본(`paulrobello/claude-office`)의 사무실 시각화를 바탕으로, 아래 게시물이 보여 준 동작을 그대로 재현한다.
게시물은 Claude Code 이야기지만 이 포크는 특정 에이전트에 묶이지 않는다. 같은 사무실 동작을 다른 코딩 에이전트에도 적용한다(아래 「에이전트 범위」).

## 출처

Threads [@cowboy76 게시물](https://www.threads.com/@cowboy76/post/DeqgY7wiJYa) 본문 원문:

> Claude Code가 터미널에서 뭘 하고 있는지 한눈에 보고 싶어서 사무실을 하나 차려줬다.
> 파일 읽을 땐 자료실 가서 책 펴고 명령 돌릴 땐 서버실 랙 앞에 서 있고 막히면 그 자리에서 턱 괴고 고민함.
> 일을 나눠 맡기면 서브에이전트가 엘리베이터 타고 출근한다 🛗 전부 내 터미널이랑 실시간으로 같이 움직임.

처음에는 첨부 영상을 볼 수 없어서 본문 문장만 근거로 삼았다. 2026-10-20 에 영상(88초)과 작성자 댓글을 확인했고, 사용자 지시로 화면을 영상과 똑같이 다시 만든다(아래 「화면 재설계」).

## 요구사항

| ID | 원문 | 화면 동작 | 트리거 (Claude Code 훅) |
|---|---|---|---|
| R1 | 파일 읽을 땐 자료실 가서 책 펴고 | 캐릭터가 자료실 책장 앞으로 걸어가 책을 펴 든다 | 도구 시작 이벤트의 도구가 읽기 도구 — Claude Code 는 `Read` · `Grep` · `Glob` · `LS` · `NotebookRead` · `WebFetch` · `WebSearch`, 다른 에이전트는 「에이전트 범위」 표 |
| R2 | 명령 돌릴 땐 서버실 랙 앞에 서 있고 | 서버실 랙 앞에 서 있는다. 랙 LED 가 깜빡인다 | 도구 시작 이벤트의 도구가 명령 도구 — Claude Code 는 `Bash` · `PowerShell` · `BashOutput` · `KillShell` · `KillBash`, 다른 에이전트는 「에이전트 범위」 표 |
| R3 | 막히면 그 자리에서 턱 괴고 고민함 | 걷지 않고 지금 자리에서 턱을 괸다. 생각 말풍선이 뜬다 | 도구 실패(`PostToolUseFailure`) · 권한 대기(`PermissionRequest`) · 턴 진행 중 도구 없이 오래 생각함 |
| R4 | 서브에이전트가 엘리베이터 타고 출근한다 | 서브에이전트가 엘리베이터에서 내려 자리로 간다 | `SubagentStart` · `PreToolUse(Agent/Task)` — 원본에 있다. 유지하고 확인한다 |
| R5 | 전부 내 터미널이랑 실시간으로 같이 움직임 | 훅 → 백엔드 → 웹소켓으로 바로 반영된다 | 모든 훅 — 원본에 있다. 실제 세션으로 확인한다 |

- `WebFetch` · `WebSearch` 는 "자료를 찾아 읽는" 일이라 R1 에 묶는다.
- 도구 실패 훅 `PostToolUseFailure` 는 `error` · `is_interrupt` · `tool_use_id` 를 준다([훅 문서](https://code.claude.com/docs/en/hooks)). 원본 훅 설치기는 이 이벤트를 등록하지 않아서 R3 에서 추가한다.
- `PermissionRequest` 입력에는 `tool_use_id` 가 없다. 권한 대기는 도구 단위가 아니라 캐릭터 단위로 판정한다.
- R1 · R2 는 사장(메인 Claude)과 서브에이전트(직원) 모두에게 적용한다. 직원 쪽은 사장 동선이 끝난 뒤 따로 붙인다.

## 에이전트 범위

사무실 동작(R1–R5)은 에이전트와 상관없이 같다. 에이전트마다 다른 것은 "어떤 도구가 읽기 · 명령인가" 와 "이벤트를 어떻게 받는가" 뿐이라, 도구 이름 → 활동 매핑을 한곳(백엔드)에 두고 대소문자를 가리지 않는다.

| 에이전트 | 이벤트 수단 (원본 기준) | R1 읽기 도구 | R2 명령 도구 |
|---|---|---|---|
| Claude Code | 훅 — 원본이 지원한다 | `Read` · `Grep` · `Glob` · `LS` · `NotebookRead` · `WebFetch` · `WebSearch` | `Bash` · `PowerShell` · `BashOutput` · `KillShell` · `KillBash` |
| OpenCode | 플러그인 `opencode-plugin/` — 원본이 지원한다 | `read` · `grep` · `glob` · `webfetch` · `websearch` | `bash` |
| Gemini CLI | 훅(`BeforeTool` · `AfterTool` …) — 원본은 조사 · 설계만 있었고 이 포크가 붙였다(09, `make gemini-hooks-install`) | `read_file` · `read_many_files` · `glob` · `grep_search` · `search_file_content` · `list_directory` · `web_fetch` · `google_web_search` | `run_shell_command` |
| Codex CLI | 훅(실험 기능) — 원본 조사(2026-04) 기준 셸 도구만 잡힌다. 붙이기 전에 현재 문서로 다시 확인한다 | 확인 필요 | `shell` 계열 |

- 도구 이름 출처: Claude Code [훅 문서](https://code.claude.com/docs/en/hooks), OpenCode [도구 문서](https://opencode.ai/docs/tools/), Gemini CLI `docs/research/google-gemini-cli-hooks.md`, Codex `docs/research/openai-codex-hooks.md`.
- Claude Code 는 서브에이전트 안에서 부른 도구 이벤트에 그 서브에이전트의 `agent_id` 를 붙인다([훅 문서](https://code.claude.com/docs/en/hooks)). 원본 훅은 이 값을 버리고 모든 도구를 사장에게 붙였다. 이 포크는 그 값으로 해당 직원을 찾아 활동을 붙인다.
- Gemini CLI 는 서브에이전트에 훅이 없어서 R4(직원 출근)가 나오지 않는다. 명령 실패는 도구 오류가 아니라 결과의 `Exit Code:` 줄로 판정한다(09 보고서).
- 사장 이름표는 지금 "Claude" 로 고정돼 있다. 세션을 띄운 에이전트 이름(Claude · OpenCode · Gemini · Codex)을 보여 주게 바꾼다.

## 화면 배치

> 2D 픽셀 사무실(재설계 전) 기준이다. 새 화면은 아래 「화면 재설계」를 따른다.

캔버스는 원본과 같은 1280×1024 를 유지한다. 지휘 센터(Command Center)가 같은 크기를 쓰고, 넓히면 화면 전체가 작아진다.

| 구역 | 위치 (캔버스 px) | 들어가는 것 |
|---|---|---|
| 자료실 | 왼쪽 아래 `x 0–320 · y 784–1024` | 책장, 프린터(원래 왼쪽 아래 있던 것을 안으로 옮긴다), 화분 |
| 서버실 | 오른쪽 아래 `x 960–1280 · y 784–1024` | 서버 랙(LED 깜빡임), 간판 |
| 도착 줄 | `A0 (480,930)` 다음부터 책상 사이 통로 `x=384` 를 따라 위로 | 방과 겹치지 않게 옮긴다 |
| 퇴근 줄 | `D0 (800,930)` 다음부터 책상 사이 통로 `x=896` 을 따라 위로 | 방과 겹치지 않게 옮긴다 |

- 두 방 모두 사장 책상(640,900)과 가깝다. 편도 약 500px 이라 2초 안에 닿는다.
- 방 벽은 위쪽 칸막이(앞면이 보이는 낮은 벽)와 안쪽 칸막이(문 뚫림)로 그린다. 문은 사장 책상 쪽을 본다.
- 간판 문구는 영어 기본(`ARCHIVE` · `SERVER ROOM`)이고 한국어 로케일에서는 `자료실` · `서버실` 이다.

## 동선 규칙

1. 활동(읽기 · 명령)이 시작되면 그 방의 빈 자리로 걸어간다. 도착하면 동작(책 펴기 · 랙 앞에 서기)을 한다.
2. 활동이 끝나도 1.5초는 그 자리에 머문다. 연달아 오는 `Read` 마다 왕복하지 않게 하기 위해서다.
3. 다른 활동이 오면 지금 자리에서 바로 다음 방으로 간다. 걷는 도중에도 목적지를 바꾼다.
4. 머무는 시간이 지나도 새 활동이 없으면 책상으로 돌아와 앉는다.
5. 말풍선과 이름표는 걷는 캐릭터를 따라간다.
6. 컨텍스트 압축 연출(쓰레기통 밟기)이 심부름보다 먼저다. 압축 중에는 심부름을 미룬다.
7. 고민(R3)은 자리를 옮기지 않는다. 자료실에서 막히면 자료실에서 턱을 괸다.

## 화면 재설계

사용자 지시(2026-10-20): "내가 처음에 준 스레드 링크의 스크린샷과 똑같은 디자인으로 만들어."
근거는 게시물 영상(88초 · 1280×618)과 작성자 댓글이다. 영상 캡처는 작성자의 저작물이라 저장소에 넣지 않고, 작업 중 비교에만 쓴다.

작성자 댓글 원문:

> 방마다 맡은 일이 있다.
> 📚 자료실: 파일 읽기, 검색 · 💻 개발실: 코드 수정 (아이맥 화면에 코드가 흐름) · 🗄️ 서버실: 명령 실행, git (돌리는 동안 랙 불빛이 빨라짐) · 🌐 정보검색실: 웹 검색, MCP 도구 · 🗒️ 회의실: 계획 세우면 화이트보드에 적음 · 🧑‍💻 내 자리: 물어볼 게 생기면 내 책상까지 찾아옴
> 생각할 땐 생각 요약이 구름 말풍선으로 뜨고, 도구가 실패하면 식은땀 흘리면서 빨간 말풍선을 띄운다.

> 제일 귀여운 건 서브에이전트다. Claude가 일을 맡기면 자기 자리에서 전화를 걸고, 새 에이전트가 엘리베이터 타고 출근함. Explore는 초록 옷에 모자, Plan은 보라 옷에 안경 쓰고 옴. 일이 끝나면 Claude 옆으로 걸어와서 결과를 보고하고 "👋 퇴근합니다!" 하고 엘리베이터 타고 사라진다. 보고하러 가다가 일을 하나 더 받으면 다시 일하러 돌아감

> 프로젝트가 여러 개면 층을 올린다. 왼쪽에 백화점 층별 안내처럼 1F는 A 프로젝트, 2F는 B 프로젝트… 그 층의 매장이 세션 하나하나다. 지금 일하는 층엔 초록불이 켜지고, 층을 누르면 "▲ 3F" 엘리베이터 표시등이 뜨면서 그 층 사무실로 이동. /clear 하면 같은 층의 새 세션으로 알아서 따라간다.

### 방 ↔ 도구

R1 · R2 를 방 일곱 곳으로 넓힌다. 백엔드 활동 계약에 활동을 더하고(`reading` · `editing` · `running` · `browsing` · `planning` · `asking`), 도구 표는 에이전트 공통으로 둔다.

| 방 | 활동 | Claude Code 도구 | 다른 에이전트 예 |
|---|---|---|---|
| 자료실 | `reading` | `Read` · `Grep` · `Glob` · `LS` · `NotebookRead`, 읽기만 하는 셸 명령 | `read_file` · `grep_search` |
| 개발실 | `editing` | `Edit` · `Write` · `MultiEdit` · `NotebookEdit` | `edit` · `write` · `patch` · `replace` · `write_file` · `apply_patch` |
| 서버실 | `running` | `Bash` · `PowerShell` · `BashOutput` · `KillShell` · `KillBash` | `run_shell_command` · `shell` |
| 정보검색실 | `browsing` | `WebFetch` · `WebSearch` · `mcp__*` | `web_fetch` · `google_web_search` |
| 회의실 | `planning` | `TodoWrite` · `EnterPlanMode` · `ExitPlanMode` · `Skill` | `todowrite` · `write_todos` · `update_plan` |
| 내 자리 | `asking` | `AskUserQuestion`, 권한 대기 | `request_user_input` · `ask_user` |

- R1 에서 `WebFetch` · `WebSearch` 를 자료실에 묶었던 것은 작성자 댓글대로 정보검색실로 옮긴다.
- 고민(R3)은 그대로 자리를 옮기지 않는다. 실패하면 식은땀과 빨간 말풍선을 더한다.

### 구현 방침

- 장면은 three.js 직교 카메라로 그린다. 가구는 상자 · 원기둥 같은 단순한 입체로, 면 밝기와 그림자는 조명으로 낸다. 이름 칩과 말풍선은 HTML 로 겹쳐(CSS2DRenderer) 글자가 또렷하다.
- 새 화면은 단계마다 머지하되, 캐릭터까지 갖출 때까지는 지금 화면을 기본으로 두고 새 화면은 따로 연다. 다 되면 기본을 바꾸고 2D 픽셀 사무실을 내린다. (20 에서 마쳤다: 기본 화면 `/` 는 등각 사무실, 2D 픽셀 사무실은 `/classic`. 26 에서 2D 픽셀 사무실을 지웠다.)
- 레이아웃 · 색 · 문구는 영상을 따르고, 데이터는 이 포크의 훅 · 백엔드에서 온다(원작은 세션 기록 jsonl 을 읽는다).

### 2D 사무실 제거

사용자 지시(2026-10-21): "그 화면은 필요없어. 관련 코드 다제거해(기능 동작에 필요한거빼고) 2D 사무실은 다 제거해버려"

- `/classic` 의 2D 픽셀 사무실과 거기에만 있던 기능(화이트보드 · 지휘 센터 · 빌딩 뷰 · 투어 · 주의 알림 · 스프라이트 도구)을 지운다.
- 등각 사무실이 쓰는 것은 남긴다: 상태 저장소 · 웹소켓 · 직원 상태 기계(출퇴근 단계) · 층별 안내 · 설정(언어 · 자동 따라가기 · 연결).
- 2D 시절의 어두운 남색 · 보라색 화면 틀(설정 창 등)은 등각 화면의 밝은 디자인으로 바꾼다.
- 2D 화면만 읽던 백엔드 데이터(화이트보드 집계 · 지휘 센터 개요 등)는 따로 걷어 낸다.

### 어두운 테마

사용자 요청(2026-10-21): "다크 테마로도 바꿀수있게 작업해줘"

- 설정 창 「일반」 탭에 「테마」를 두고 「밝게」(기본) · 「어둡게」 중에서 고른다. 고른 값은 언어처럼 백엔드 설정(`theme`)에 저장한다.
- 브라우저에도 같은 값을 남겨, 어둡게 둔 사람이 화면을 새로 열 때 밝은 화면이 먼저 번쩍이지 않게 한다.
- 어둡게 고르면 화면 틀(층별 안내 · 머리말 · 오른쪽 패널 · 버튼 · 폰에서 덮어 여는 창 · 설정 창)과 사무실 위의 이름 칩 · 말풍선이 어두운 남색 계열로 바뀐다.
- 사무실은 불을 켠 밤 사무실이다(사용자 피드백 — 「사무실에 조명은 들어와야될거같은데」). 실내는 낮처럼 밝되 조명을 조금 따뜻하게 하고, 창밖 하늘과 빌딩만 밤 색으로 바꾼다. 사무실 둘레는 어두운 배경이다. 방 · 가구 · 사람의 배치와 색은 그대로다.

### 오른쪽 패널 정리

사용자 요청(2026-10-21): "어디서 무엇을 하나는 제거", "사무실 사람들 -> 사무실"
같은 날 정정: "어디서 무엇을 하나 제목만 지우라는의미였고 지우지말고 다른 제목을 ㅗ바꾸자", "사무실 안내도로 진행"

- 오른쪽의 방 범례 카드는 그대로 두고 제목만 「어디서 무엇을 하나」에서 「사무실 안내도」로 바꾼다(Office map · Plano de la oficina · Mapa do escritório). 35 에서 카드째 지웠던 것을 36 에서 되살렸다.
- 「사무실 사람들」 카드의 제목을 「사무실」로 바꾼다. 다른 언어도 같은 뜻으로 줄인다(Office · Oficina · Escritório).
- 위 「화면 구성」 표는 영상에서 읽은 기록이라 그대로 둔다.

### 라운지 · 카페

라운지와 카페는 그림만 있고 아무도 가지 않았다. 원작 댓글이 하는 일을 적은 방이 여섯 곳뿐이라 그대로 따랐기 때문이다.
사용자 질문(2026-10-21): "라운지랑 카페는 안써?" — 제안 세 가지에 "좋아 그렇게 진행하면되겠음"

- 라운지: 할 일이 없는 직원이 소파에서 쉰다. 응답을 마치고(턴이 끝나고) 다음 질문을 기다리는 Claude 는 라운지 소파에 앉아 있다가, 새 질문이 오면 곧장 자기 자리로 돌아간다. 처음 연 화면에서 턴이 끝나 있으면 소파에 앉은 채로 그린다.
- 카페: 일을 마친 서브에이전트는 Claude 에게 보고하고 「👋 퇴근합니다!」 한 뒤, 엘리베이터로 가기 전에 카페에 잠깐 들러 커피를 마신다. 그 사이 일을 더 받으면 곧장 일하러 간다.
- 카페: 대화 기록을 압축하는 동안 Claude 가 카페에서 커피를 마신다. 압축은 시작 신호(`context_compaction`)만 오므로, 그 뒤 첫 이벤트가 올 때까지를 압축 중으로 본다. 그동안 「고민 중」 대신 「☕ 대화 정리 중」 말풍선을 띄운다. 도구가 오면 그 방으로, 아니면 자리로(턴이 끝났으면 라운지로) 곧장 간다.
- 사무실 안내도에 라운지 · 카페 줄을 더한다.
- 라운지에서 멍하니 있지 않는다(사용자 요청 — 「라운지에 멍때리고있지말고 커피를 마시던 이런 류의 기믹을 좀 추가하면어떨까」, 제안에 「ㅇㅋ 라운지는 그런 동작 기믹을 넣고」). 쉬는 동안 25초마다 커피 → 휴대폰 → 책 → TV 를 돌아가며 하고, 마지막 이벤트 뒤 5분이 지나면 꾸벅꾸벅 졸며 「💤」 말풍선을 띄운다. TV 를 보는 동안에는 TV 화면이 켜진다.

### 작업 공간 기믹

사용자 요청(2026-10-21): 라운지 말고도 넣을 만한 기믹 제안 표에 "이거 다 반영해서 작업해"

- 내 자리(나): 질문을 보내는 순간(`user_prompt_submit`) 「나」가 몇 초 동안 키보드를 두드린다.
- 서버실: 명령이 10초 넘게 돌면 기다리는 사람이 팔짱을 끼고 손목시계를 본다.
- 회의실: 할 일 목록을 쓸 때(`TodoWrite` 등) 할 일 수만큼 화이트보드에 포스트잇이 붙는다.
- 정보검색실: 웹 · MCP 도구를 쓰는 동안 지구본이 빙글빙글 돈다.
- 자료실: 자료실에 머물며 읽기 도구를 쓸 때마다 그 사람 앞에 책이 한 권씩 쌓이고(최대 6권), 자료실을 떠나면 치운다.
- 개발실: 고치는 동안 가끔 머리를 긁고, 테스트 명령(`test` 가 든 셸 명령)이 성공하면 만세를 한다.
- 엘리베이터: 서브에이전트가 내릴 때 문 위 표시등이 켜진다.
