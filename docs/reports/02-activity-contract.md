# 02 · 활동 계약 — 누가 무엇을 하는지 백엔드가 알려 준다

- 브랜치: `feat/02-activity-contract`
- 근거: [근거 문서](../plan/spec.md) R1 · R2 · 「에이전트 범위」

## 목표

캐릭터(사장 · 직원)마다 "지금 읽는 중(`reading`) / 명령 중(`running`) / 아무것도 아님" 을 백엔드가 계산해 화면 상태에 싣는다. 03 · 05 의 걸어가기는 이 값만 보고 움직인다. 이 항목에서 화면 움직임은 아직 바뀌지 않는다.

## 한 일

- `backend/app/core/activity.py` — 도구 이름 → 활동 표(대소문자 무시). Claude Code · OpenCode · Gemini CLI · Codex CLI 도구를 한 표에 담았다. 도구가 겹쳐도 맞게 캐릭터별로 진행 중 도구를 기록하고, 가장 최근에 시작해 아직 안 끝난 도구의 활동을 낸다.
- `Boss.activity` · `Agent.activity` (`backend/app/models/agents.py`). 도구 시작 · 끝(성공 · 실패) · 서브에이전트 종료 · 턴 시작 · 턴 종료 · 세션 종료에서 갱신된다.
- **서브에이전트 도구 귀속 수정** — Claude Code 는 서브에이전트 안에서 부른 도구에 그 서브에이전트의 `agent_id` 를 붙여 보내는데, 원본 훅은 이 값을 버리고 모든 도구를 사장에게 붙였다. 훅이 이 값을 `native_agent_id` 로 넘기고, 백엔드가 연결된 직원을 찾는다. 연결을 놓쳤으면 종료 처리와 같은 규칙(대기 중인 미연결 직원부터)으로 붙인다.
- **`PostToolUseFailure` 훅 등록** — 실패한 도구는 `PostToolUse` 가 오지 않아 "명령 중" 이 풀리지 않는다. 실패를 `success=false` 인 끝 이벤트로 보낸다. 오류는 첫 줄만(`Exit code 1`) 싣는다.
- 프런트 타입 재생성(`make gen-types`) · 저장소(`boss.activity` · 에이전트 `activity`) · 상태 재조정기 연결.
- 시뮬레이터 시나리오 `errands`(약 70초): 사장이 연속 읽기 → grep → 테스트 실행 → 편집 → 실패한 실행 → 수정 → 재실행, 서브에이전트가 읽기 · 명령. 모든 도구 이벤트에 `tool_use_id` 를 싣는다.
